# knowledge-base 开发步骤跟踪文档

本文档用于记录 `knowledge-base` 项目的开发进度。Agent 每次继续开发前，应先阅读本文档和 `personal/docs/知识库开发文档.md`，确认当前步骤、已完成内容、下一步任务和注意事项。

## 使用规则

1. 开发前先查看“当前进度”区域，确认当前正在进行哪一步。
2. 每完成一个步骤，必须把对应步骤的状态从 `[ ]` 改为 `[x]`。
3. 如果某一步只完成了一部分，保持 `[ ]`，并在“进度备注”里写清楚已完成和未完成内容。
4. 每次中断前，必须更新“当前进度”。
5. 如果实现过程中发现开发文档需要调整，先更新 `personal/docs/知识库开发文档.md`，再更新本文档。
6. 每个大阶段完成后，至少运行一次对应验证命令，并把结果写入“验证记录”。

## 状态标记说明

```text
[ ] 未开始或未完成
[x] 已完成
[~] 进行中或部分完成，不建议长期保留；中断前应写清备注
[!] 阻塞，需要用户确认或解决问题
```

## 中断恢复说明

如果开发中断，新的 Agent 应按以下流程恢复：

1. 阅读 `personal/docs/开发步骤.md` 的“当前进度”。
2. 查看最近一个未完成 `[ ]` 或 `[~]` 的步骤。
3. 阅读该步骤的“进度备注”。
4. 查看 `personal/docs/知识库开发文档.md` 中对应模块的需求和接口说明。
5. 检查代码仓库当前状态和 git diff。
6. 运行当前阶段相关验证命令。
7. 从未完成的最小步骤继续开发。
8. 完成后更新本文档。

## 重要提醒

- 不要跳过权限校验。
- 不要把密码、token 写入日志或审计日志。
- 不要直接公开 uploads 目录。
- 不要让普通用户访问 `/api/admin/*`。
- 不要手动改数据库表，使用 Prisma migration。
- 不要在未更新本文档的情况下中断开发。
