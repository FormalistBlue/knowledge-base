# knowledge-base 知识库开发文档

本文档用于指导 `knowledge-base` 部门内部知识库平台的完整开发。目标是让开发者只根据本文档，就能理解需求、数据库关系、接口结构、权限规则、前后端模块划分和关键实现方式。

## 1. 项目概述

### 1.1 项目定位

`knowledge-base` 是一个部门内部使用的轻量知识库平台，长期用户规模约 20 人。所有登录用户都可以查看知识内容，普通成员可以发布和维护自己的知识，管理员负责用户、分类、标签、文章、评论和统计管理。

系统主要服务以下内容：

- 技术文档
- 操作流程 / SOP
- 规范要求
- 产品介绍文档
- 部门经验沉淀

### 1.2 第一版目标

第一版需要完成以下能力：

- 管理员手动创建用户
- 用户使用用户名 + 密码登录
- 登录后长期保持登录状态，约 20 天内无需重新输入密码
- 用户可以修改自己的密码
- 管理员可以重置用户密码、禁用用户
- 禁用用户不能登录，已有 token 也不能继续访问接口
- 用户可以发布 Markdown + 所见即所得知识内容
- 知识支持摘要、多级分类、多个标签、草稿、发布、归档
- 普通用户只能编辑/删除自己的知识
- 管理员可以编辑/删除所有知识
- 所有登录用户都可以查看已发布知识
- 草稿只有作者和管理员可见
- 归档知识列表默认不显示，但详情页仍可访问
- 支持标题、正文、标签的简单模糊搜索
- 支持分类、标签、发布时间筛选
- 支持图片上传和附件上传
- 支持临时上传，文章保存后再绑定文件
- 支持图片和 PDF 预览，Office 文件和压缩包第一版只下载
- 支持点赞、收藏、浏览数
- 浏览数做简单防刷
- 支持两层评论：评论 + 回复
- 删除父评论时，其子回复一起软删除
- 支持站内通知，用户可以标记已读和删除通知
- 后台支持用户、分类、标签、文章、评论、统计管理
- 关键操作记录审计日志
- 支持暗色模式
- 支持 Docker Compose 部署

### 1.3 暂不实现的能力

第一版暂不实现：

- 多部门权限
- 完整 RBAC 权限系统
- 内容审核流程
- 历史版本回滚
- AI 问答
- Elasticsearch / OpenSearch
- Office 在线预览或在线编辑
- 实时协作编辑
- 移动端专项适配
- 企业微信 / 飞书 / 钉钉集成

## 4. 通用后端规范

### 4.1 统一响应结构

所有 JSON 接口建议使用统一结构。

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "参数校验失败",
  "details": []
}
```

### 4.2 常用错误码

```text
UNAUTHORIZED          未登录或 token 无效
FORBIDDEN             没有权限
VALIDATION_ERROR      参数校验失败
NOT_FOUND             资源不存在
CONFLICT              资源冲突，例如用户名重复
USER_DISABLED         用户已禁用
TOKEN_EXPIRED         token 已过期
TOKEN_REVOKED         token 已失效，例如密码被重置
FILE_TOO_LARGE        文件过大
FILE_TYPE_NOT_ALLOWED 文件类型不允许
INTERNAL_ERROR        服务端异常
```

### 4.3 分页结构

列表接口统一使用：

请求参数：

```text
page: number，默认 1
pageSize: number，默认 20，最大 100
```

响应：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 100,
  "totalPages": 5
}
```

### 4.4 时间格式

接口返回时间统一使用 ISO 字符串：

```text
2026-04-30T10:00:00.000Z
```

前端展示时再格式化为本地时间。

### 4.5 参数校验

所有后端入参必须使用 Zod 校验：

- `req.body`
- `req.query`
- `req.params`

禁止在业务代码中直接相信前端传入的数据。

## 5. 鉴权与权限设计

### 5.1 登录方案

第一版使用：

- JWT access token
- token 存放在前端 localStorage
- token 有效期 20 天
- 请求头使用 `Authorization: Bearer <token>`

说明：localStorage 实现简单，适合学习项目。但它对 XSS 更敏感，所以前端必须认真处理 Markdown 渲染的 XSS 清理。

### 5.2 token 立即失效机制

用户重置密码或修改密码后，旧 token 必须立即失效。

实现方式：在 `users` 表增加 `token_version` 字段。

- 登录成功时，把当前用户的 `token_version` 写入 JWT payload
- auth middleware 每次校验 token 后，从数据库读取用户
- 如果 token 中的 `tokenVersion` 不等于数据库中的 `token_version`，返回 `TOKEN_REVOKED`
- 用户修改密码或管理员重置密码时，`token_version + 1`

JWT payload 示例：

```json
{
  "sub": "user_id",
  "role": "admin",
  "tokenVersion": 3,
  "iat": 1770000000,
  "exp": 1771728000
}
```

### 5.3 角色

第一版只有两个角色：

```text
admin 管理员
user  普通用户
```

### 5.4 权限规则

管理员可以：

- 创建用户
- 禁用用户
- 重置用户密码
- 管理分类
- 管理标签
- 管理所有文章
- 管理所有评论
- 设置文章置顶
- 修改文章分类和标签
- 查看统计
- 查看审计日志

普通用户可以：

- 查看所有已发布知识
- 查看所有归档知识详情
- 创建知识
- 编辑自己的知识
- 删除自己的知识
- 查看自己的草稿
- 点赞
- 收藏
- 评论
- 回复评论
- 上传图片和附件
- 查看自己的通知
- 修改自己的密码

### 5.5 中间件

需要实现三个核心中间件：

```text
authMiddleware   校验登录，解析当前用户
adminMiddleware  校验当前用户 role 是否为 admin
ownerCheck        在��体业务中判断资源是否属于当前用户
```

后端权限必须真实校验，不能只靠前端隐藏按钮。

## 6. 数据库设计

以下字段类型以 Prisma + PostgreSQL 为准，具体字段名建议使用 camelCase，在数据库中 Prisma 会映射为对应列名。

### 6.1 User 用户表

用途：保存登录用户、角色、账号状态和 token 失效版本。

字段：

```text
id              String   @id @default(cuid())
username        String   @unique
passwordHash    String
displayName     String
role            UserRole @default(USER)
status          UserStatus @default(ACTIVE)
tokenVersion    Int      @default(0)
lastLoginAt     DateTime?
createdAt       DateTime @default(now())
updatedAt       DateTime @updatedAt
deletedAt       DateTime?
```

枚举：

```text
UserRole: ADMIN, USER
UserStatus: ACTIVE, DISABLED
```

关系：

- 一个用户可以发布多篇知识
- 一个用户可以创建多个标签
- 一个用户可以上传多个附件
- 一个用户可以有多个点赞、收藏、评论、通知

### 6.2 Category 分类表

用途：保存多级分类，例如 `技术文档 > 前端 > Vue`。

字段：

```text
id          String @id @default(cuid())
name        String
parentId    String?
sortOrder   Int    @default(0)
createdAt   DateTime @default(now())
updatedAt   DateTime @updatedAt
deletedAt   DateTime?
```

约束和规则：

- `parentId` 指向同表 `categories.id`
- 分类支持多级，但前端展示建议控制在 3-4 层以内
- 有子分类时禁止删除
- 有文章绑定时禁止删除
- 同一父级下分类名建议唯一
- 更新分类父级时必须避免循环引用

关系：

- 一个分类可以有多个子分类
- 一个分类可以绑定多篇知识
- 一篇知识只能属于一个分类

### 6.3 Tag 标签表

用途：保存文章标签。

字段：

```text
id             String @id @default(cuid())
name           String
normalizedName String @unique
createdById    String?
createdAt      DateTime @default(now())
updatedAt      DateTime @updatedAt
deletedAt      DateTime?
```

规则：

- 用户可以创建标签
- 管理员可以编辑和删除标签
- `Vue` 和 `vue` 视为同一个标签
- 保存时对标签名 `trim`
- `normalizedName = name.trim().toLowerCase()`
- 删除标签时自动解除和文章的关联

### 6.4 KnowledgeItem 知识表

用途：保存知识文章正文和基础信息。

字段：

```text
id           String @id @default(cuid())
title        String
summary      String
content      String
status       KnowledgeStatus @default(DRAFT)
categoryId   String
authorId     String
isPinned     Boolean @default(false)
viewCount    Int @default(0)
publishedAt  DateTime?
archivedAt   DateTime?
createdAt    DateTime @default(now())
updatedAt    DateTime @updatedAt
deletedAt    DateTime?
```

枚举：

```text
KnowledgeStatus: DRAFT, PUBLISHED, ARCHIVED
```

规则：

- 标题必填，建议 2-100 字
- 摘要必填，建议 1-300 字
- 正文必填，保存 Markdown 内容
- 一篇知识只能属于一个分类
- 一篇知识可以有多个标签
- 草稿只有作者和管理员能看
- 已发布知识所有登录用户可看
- 归档知识列表默认不显示，但详情页仍可访问
- 删除使用软删除，不做恢复页面
- 普通用户只能编辑/删除自己的知识
- 管理员可以编辑/删除所有知识
- 管理员可以设置 `isPinned`

### 6.5 KnowledgeTag 知识标签关联表

用途：实现知识和标签多对多。

字段：

```text
knowledgeId String
tagId       String
createdAt   DateTime @default(now())
```

约束：

```text
unique(knowledgeId, tagId)
```

关系：

- 一篇知识可以有多个标签
- 一个标签可以关联多篇知识

### 6.6 KnowledgeLike 点赞表

用途：记录用户点赞。

字段：

```text
id          String @id @default(cuid())
knowledgeId String
userId      String
createdAt   DateTime @default(now())
```

约束：

```text
unique(knowledgeId, userId)
```

规则：

- 同一用户对同一篇知识只能点赞一次
- 再次点赞接口应保持幂等，不应产生重复数据

### 6.7 KnowledgeFavorite 收藏表

用途：记录用户收藏。

字段：

```text
id          String @id @default(cuid())
knowledgeId String
userId      String
createdAt   DateTime @default(now())
```

约束：

```text
unique(knowledgeId, userId)
```

规则：

- 同一用户对同一篇知识只能收藏一次

### 6.8 KnowledgeView 浏览记录表

用途：做简单浏览数防刷。

字段：

```text
id          String @id @default(cuid())
knowledgeId String
userId      String
viewDate    DateTime
createdAt   DateTime @default(now())
```

约束：

```text
unique(knowledgeId, userId, viewDate)
```

实现规则：

- `viewDate` 只保存当天日期，例如当天 00:00:00
- 同一用户同一天查看同一篇知识，只增加一次 `viewCount`
- 访问详情时，后端尝试创建浏览记录
- 如果创建成功，则 `knowledge_items.view_count + 1`
- 如果唯一约束冲突，则不增加浏览数

### 6.9 Comment 评论表

用途：保存文章评论和回复。

字段：

```text
id          String @id @default(cuid())
knowledgeId String
userId      String
parentId    String?
content     String
createdAt   DateTime @default(now())
updatedAt   DateTime @updatedAt
deletedAt   DateTime?
```

规则：

- 评论支持 Markdown
- 只支持两层：评论 + 回复
- 顶级评论的 `parentId = null`
- 回复的 `parentId` 指向顶级评论
- 不允许回复一个回复
- 删除父评论时，其子回复一起软删除
- 普通用户只能删除自己的评论
- 管理员可以删除任意评论

### 6.10 Attachment 附件表

用途：统一保存图片和附件元数据。

字段：

```text
id            String @id @default(cuid())
knowledgeId   String?
uploaderId    String
usageType     AttachmentUsageType
status        AttachmentStatus @default(TEMP)
originalName  String
storedName    String
relativePath  String
fileSize      Int
mimeType      String
extension     String
createdAt     DateTime @default(now())
boundAt       DateTime?
deletedAt     DateTime?
```

枚举：

```text
AttachmentUsageType: IMAGE, ATTACHMENT
AttachmentStatus: TEMP, BOUND
```

规则：

- 图片和附件都存在 attachments 表
- 上传时可以先是临时文件，`status = TEMP`，`knowledgeId = null`
- 文章创建或编辑保存时，把对应文件绑定到文章，`status = BOUND`
- 临时文件可以通过定时任务清理，例如超过 24 小时仍未绑定则软删除并删除物理文件
- 文件名必须由服务端生成，禁止直接使用用户原始文件名作为存储路径
- 下载和预览接口必须登录后才能访问
- 上传大小限制 50MB

允许类型：

```text
图片：jpg, jpeg, png, gif, webp
文档：pdf, doc, docx, xls, xlsx, ppt, pptx, txt, md
压缩包：zip, rar, 7z
```

预览规则：

- 图片：浏览器直接预览
- PDF：浏览器 iframe 或新窗口预览
- Word / Excel / PPT：第一版只下载
- 压缩包：只下载

### 6.11 Notification 通知表

用途：保存站内通知。

字段：

```text
id          String @id @default(cuid())
userId      String
type        NotificationType
title       String
content     String
relatedType String?
relatedId   String?
isRead      Boolean @default(false)
createdAt   DateTime @default(now())
readAt      DateTime?
deletedAt   DateTime?
```

枚举：

```text
NotificationType:
- KNOWLEDGE_COMMENTED
- COMMENT_REPLIED
- PASSWORD_RESET
- KNOWLEDGE_UPDATED_BY_ADMIN
```

第一版必须实现：

- 文章被评论时，通知文章作者
- 评论被回复时，通知原评论作者

注意：

- 自己评论自己的文章不需要通知自己
- 自己回复自己的评论不需要通知自己
- 用户可以标记已读
- 用户可以删除自己的通知，使用软删除

### 6.12 AuditLog 操作日志表

用途：记录关键后台操作。

字段：

```text
id          String @id @default(cuid())
actorId     String
action      AuditAction
targetType  String
targetId    String?
summary     String
metadata    Json?
createdAt   DateTime @default(now())
```

枚举：

```text
AuditAction:
- CREATE_USER
- DISABLE_USER
- ENABLE_USER
- RESET_PASSWORD
- DELETE_KNOWLEDGE
- PIN_KNOWLEDGE
- UPDATE_KNOWLEDGE_CATEGORY
- UPDATE_KNOWLEDGE_TAGS
- DELETE_COMMENT
- DELETE_CATEGORY
- DELETE_TAG
```

规则：

- 只记录关键操作
- 不记录用户密码明文
- `metadata` 可存操作前后的关键字段，但不要存敏感信息

## 7. Prisma Schema 示例

以下是核心 schema 的结构示例，实际开发时可以根据 Prisma 格式微调。

```prisma
enum UserRole {
  ADMIN
  USER
}

enum UserStatus {
  ACTIVE
  DISABLED
}

enum KnowledgeStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}

enum AttachmentUsageType {
  IMAGE
  ATTACHMENT
}

enum AttachmentStatus {
  TEMP
  BOUND
}

model User {
  id           String     @id @default(cuid())
  username     String     @unique
  passwordHash String
  displayName  String
  role         UserRole   @default(USER)
  status       UserStatus @default(ACTIVE)
  tokenVersion Int        @default(0)
  lastLoginAt  DateTime?
  createdAt    DateTime   @default(now())
  updatedAt    DateTime   @updatedAt
  deletedAt    DateTime?

  knowledgeItems KnowledgeItem[]
  comments       Comment[]
  likes          KnowledgeLike[]
  favorites      KnowledgeFavorite[]
  attachments    Attachment[]
  notifications  Notification[]
}

model Category {
  id        String   @id @default(cuid())
  name      String
  parentId  String?
  activeKey String   @unique
  sortOrder Int      @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?

  parent   Category?  @relation("CategoryTree", fields: [parentId], references: [id])
  children Category[] @relation("CategoryTree")
  items    KnowledgeItem[]

  @@index([parentId])
  @@index([deletedAt])
}

model Tag {
  id             String   @id @default(cuid())
  name           String
  normalizedName String   @unique
  createdById    String?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
  deletedAt      DateTime?

  createdBy User? @relation(fields: [createdById], references: [id])
  items     KnowledgeTag[]
}

model KnowledgeItem {
  id          String          @id @default(cuid())
  title       String
  summary     String
  content     String
  status      KnowledgeStatus @default(DRAFT)
  categoryId  String
  authorId    String
  isPinned    Boolean         @default(false)
  viewCount   Int             @default(0)
  publishedAt DateTime?
  archivedAt  DateTime?
  createdAt   DateTime        @default(now())
  updatedAt   DateTime        @updatedAt
  deletedAt   DateTime?

  category    Category @relation(fields: [categoryId], references: [id])
  author      User     @relation(fields: [authorId], references: [id])
  tags        KnowledgeTag[]
  likes       KnowledgeLike[]
  favorites   KnowledgeFavorite[]
  comments    Comment[]
  attachments Attachment[]
  views       KnowledgeView[]

  @@index([status])
  @@index([categoryId])
  @@index([authorId])
  @@index([publishedAt])
  @@index([isPinned])
}

model KnowledgeTag {
  knowledgeId String
  tagId       String
  createdAt   DateTime @default(now())

  knowledge KnowledgeItem @relation(fields: [knowledgeId], references: [id], onDelete: Cascade)
  tag       Tag           @relation(fields: [tagId], references: [id], onDelete: Cascade)

  @@id([knowledgeId, tagId])
}

model KnowledgeLike {
  id          String   @id @default(cuid())
  knowledgeId String
  userId      String
  createdAt   DateTime @default(now())

  knowledge KnowledgeItem @relation(fields: [knowledgeId], references: [id])
```

## 8. 接口设计

### 8.1 Auth 认证模块

#### POST /api/auth/login

说明：用户名密码登录。

请求：

```json
{
  "username": "admin",
  "password": "123456"
}
```

响应：

```json
{
  "token": "jwt_token",
  "expiresIn": 1728000,
  "user": {
    "id": "user_id",
    "username": "admin",
    "displayName": "管理员",
    "role": "ADMIN",
    "status": "ACTIVE"
  }
}
```

业务规则：

- 用户不存在返回 `UNAUTHORIZED`
- 密码错误返回 `UNAUTHORIZED`
- 用户已禁用返回 `USER_DISABLED`
- 登录成功更新 `lastLoginAt`
- token 有效期 20 天

#### POST /api/auth/logout

说明：第一版服务端不维护 token 黑名单，登出由前端清除 localStorage token。接口可以返回成功，便于前端统一调用。

响应：

```json
{
  "success": true
}
```

#### GET /api/auth/me

说明：获取当前登录用户。

响应：

```json
{
  "id": "user_id",
  "username": "admin",
  "displayName": "管理员",
  "role": "ADMIN",
  "status": "ACTIVE"
}
```

#### POST /api/auth/change-password

说明：用户修改自己的密码。

请求：

```json
{
  "oldPassword": "old_password",
  "newPassword": "new_password"
}
```

业务规则：

- 必须登录
- 校验旧密码
- 新密码建议至少 8 位
- 修改成功后 `tokenVersion + 1`
- 当前 token 也会失效，前端需要跳转登录页重新登录

## 10. 文件存储设计

### 10.1 存储目录

建议：

```text
data/uploads/
  images/
    2026/04/30/
  attachments/
    2026/04/30/
```

实际文件名使用服务端生成：

```text
cuid + 原扩展名
```

例如：

```text
clx123abc.png
```

### 10.2 为什么不能直接公开 uploads

不能直接把 uploads 映射成公开静态目录，因为所有知识内容只允许登录用户访问。

正确方式：

- 文件预览走 `/api/files/:id/preview`
- 文件下载走 `/api/files/:id/download`
- 后端先校验登录和文件状态
- 校验通过后再用 `res.sendFile` 或 stream 返回

### 10.3 临时文件绑定

流程：

1. 用户在编辑器里上传图片或附件
2. 后端保存文件，attachments.status = TEMP
3. 前端拿到 attachmentId
4. 用户保存文章时提交 attachmentIds
5. 后端创建/更新文章后，把这些附件更新为 BOUND，并设��� knowledgeId
6. 定时清理 24 小时前未绑定的临时文件

## 11. 搜索实现

第一版使用 PostgreSQL 简单模糊搜索。

搜索范围：

- knowledge_items.title
- knowledge_items.content
- tags.name

基础逻辑：

```text
WHERE knowledge.deletedAt IS NULL
AND status = PUBLISHED
AND (
  title ILIKE '%keyword%'
  OR content ILIKE '%keyword%'
  OR exists tag.name ILIKE '%keyword%'
)
```

排序：

- 置顶优先
- 默认按 publishedAt desc
- 热门按 viewCount desc

后续如果搜索质量不够，再升级为：

- PostgreSQL Full Text Search
- pg_trgm 模糊匹配
- Meilisearch
- Elasticsearch

## 12. 安全要求

### 12.1 密码安全

- 密码使用 bcrypt hash
- 不保存明文密码
- 日志和审计日志中不能保存密码
- 重置密码后 tokenVersion + 1

### 12.2 XSS 防护

- Markdown 渲染后必须使用 DOMPurify 清理
- 评论 Markdown 也必须清理
- 文件名展示时也要避免直接插入 HTML

### 12.3 文件安全

- 限制文件大小 50MB
- 限制扩展名白名单
- 校验 MIME 类型
- 服务端生成存储文件名
- 防止路径穿越
- 下载和预览必须鉴权

### 12.4 权限安全

- 所有业务接口默认需要登录
- `/api/admin/*` 必须管理员权限
- 编辑/删除文章时校验作者或管理员
- 删除评论时校验评论作者或管理员
- 禁用用户已有 token 不能继续访问

## 16. 开发建议

建议先打通最小主链路：

```text
项目初始化 -> 数据库 -> 登录 -> 用户管理 -> 分类标签 -> 发布知识 -> 查看知识
```

再继续扩展：

```text
上传 -> 搜索 -> 点赞收藏 -> 评论 -> 通知 -> 后台统计 -> 部署
```

不要一开始就追求所有细节完美。先确保主流程可用，再逐步补齐安全、交互和后台能力。
